# ADR 138 — Opt-in coding reasoning and observed publisher integration

**Purpose:** Address the specific remaining D46 coding and D60 publisher-link gaps while preserving approved models, existing services and immutable first measurements.

Date: 2026-11-02. Status: Accepted for implementation and bounded validation under the owner's explicit request to work on D46 and D60. No production activation or model replacement.

## Assessment and decision

D46 P1: CE003 retains first/eventual4/6; last-delimiter semantics fail and an added import/signature change is rejected. Dependency: existing controlled workflow, native check/patch approvals and the already qualified D14 bounded-reasoning implementation. Effort: one optional adapter/service plus fresh frozen evaluation. Add a named `coding_reasoning_v1` mode (512 native reasoning tokens within1024 total), structural plan/replacement grammar and a generic preservation instruction. This is explicitly not the fast preset. The base service reads a trusted class mode, defaultfast unchanged; only an unregistered subclass selects the new mode. Existing60second workflow budget, owner/source fences and all native approval requirements remain. Count the actual thinking prompt before generation; reject excess context. No repair, answer enumeration, hidden feedback or automatic retry.

D60 P1: actual Brave RFC landing discovery does not itself provide full text. Dependency: accepted public HTTPS transport, bounded fetch, signed WebEvidenceService and observed-link experiment ADR131. Effort: one optional reusable resolver plus owner/source/SSRF/cancellation tests and fresh source acquisition. Follow one actually observed HTML anchor under a trusted exact parent/child policy, then acquire a new signed child snapshot. Keep discovery, landing and child provenance distinct; the child is never relabeled a search hit. Do not bypass parent hashes, revive archived proofs or fetch guessed fallback URLs. Existing Brave provider and direct-result failure remain unchanged.

## Risks, acceptance and rollback

Risks: preset mislabeling, narrowed code-output capacity, source/API drift, hidden oracle leakage, selecting scores, parent/link substitution, extra fetch latency, redirects and orphan tasks. Freeze new cases/oracles and implementation before inference. Require complete first outcomes, unchanged fixture review, real native visible+held-out checks and exact request/cleanup evidence. Software tests do not alone close coding quality or broad live-web reliability. Report failures without changing the frozen criterion; no statistical or unattended-production claim from a small authored cohort.

The coding mode supports utility files fitting4096characters and8192UTF-8bytes; larger requests are not certified. No historical case is regenerated for a replacement score. Model identities/config/weights/context, existing API defaults and Vault/database/Qdrant/provider choices remain unchanged. Rollback omits both optional components and retains defaultfast, original fetch/evidence services and every first-score artifact. Shared source changes require scoped regression and a new full run before a current full-suite claim.
