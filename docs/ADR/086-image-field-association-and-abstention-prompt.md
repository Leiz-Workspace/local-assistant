# ADR 086 Explicit image field association and abstention

**Purpose:** Repair the observed D61 unsupported-field answer through generic fixed-model instructions while preserving the first failure and unchanged measurement oracles.

**Date:** 2026-10-22. **Status:** Accepted for a necessary new-component-only prompt repair and distinct same-oracle qualification; no D61 PASS from the repair itself.

The first frozen D61 actual sample returns correct Invoice2048/Total42USD and Bút3/Vở5, but answers the absent customer-name question with the document heading LOCAL OCR GOLDEN. The uncertainty array admits the heading may only be a label, yet the answer promotes it into a named field. This is a functional2/3 failure, despite valid schemas/provenance, joined cleanup and successful ordinary text recovery. Original first source/test/freeze/output/log bytes are preserved in a complete private ZIP and public first result; never rewrite that score as3/3.

P1/current D61 acceptance dependency; depends on the original three frozen image/question/oracle samples and existing unchanged CORE. Effort one generic system-frame clarification, controlled protocol/privacy replay, distinct actual same-oracle run and related/final readonly checks. Risks: teaching fixture-specific answers, hiding model hallucination behind a schema, retrying unchanged code until success, treating tiny visible samples as general accuracy and changing model/pixels/labels after a failure.

Change only the new vision-chat system frame. A requested document field requires a visible label or unambiguous layout associating the value with that field. Titles/headings/logos do not establish unrelated identities. When this association is ambiguous or absent, abstain in answer and describe the ambiguity in uncertainties; never place a tentative candidate into answer and rely on an uncertainty disclaimer to make it supported. Do not include the fixture heading/customer answer, expected IDs/numbers, source image text or per-case oracle in the system prompt. No host answer rewriting or semantic-certification heuristic.

Keep complete decoded user questions/normalized images, field schemas, model/temperature/seed/token/cache/deadline/quota/normalizer/HTTP/owner/cancel options and original expected patterns/labels unchanged. One distinct run after source/oracle freeze, one attempt per case; preserve any subsequent failure. The earlier2/3 remains the first measurement. The output is still unverified and never grants action/citation authority even if all visible cases pass. Broader abstention/OCR/VLM evaluation remains D62/D63, not inferred here.

Rollback drains only the new service and restores the exact previous new-module bytes from the retained ZIP; all545 pre-D61 source/config bytes, models/projector/data/services and original artifacts remain unchanged.
