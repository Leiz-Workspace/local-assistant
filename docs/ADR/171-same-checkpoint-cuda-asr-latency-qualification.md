Keep the exact original14ASR artifacts and their tokenizer/processor/source. Qwen runs float32/eager with TF32/autocast disabled, seed7 and identical generation/language controls. Whisper retains the original CTranslate2 4.6.0/int8_float32 engine and beam5/settings, but uses CUDA. Existing weights/SDKs/app/source and the failing CPUcohort remain immutable. Trúc Ly stays CPUFP32/8threads; ADR170 observed identical ASR/CORE/native float audio bytes across2/4/8CPUprofiles on all16comparisons, so CPU8 is an execution allocation, not a changed voice or renderer.

Prepare an isolated Python3.12 CUDA runtime with exactly `torch==2.10.0+cu128`, the same2.10core version as original CPU, from the [official CUDA128 index](https://download.pytorch.org/whl/cu128/torch/), plus pinned loader-only `accelerate==1.12.0`/`psutil==7.0.0`. Reuse the original ASR Python packages readonly after the CUDA environment on the import path; verify actual origins/versions. `uv` lock/hash/install logs, package inventory and a private8GiB SDK-root cap; software packages only, no model download. [CTranslate2 GPU installation](https://opennmt.net/CTranslate2/installation.html) documents supported CUDA execution and compute-type discovery; the actual installed4.6.0 probe reports int8_float32 supported. Driver580.178.04/RTX4070TiSUPER observed locally.

The GPU address-space profile is explicit and separate:64GiB virtual-address cap for CUDA mappings, **not64GiB RAM**. CPUprofiles keep their old8GiB virtual caps. Physical sampled aggregate worker+ownedCORE RSS remains≤8GiB, TTS RSS≤2GiB, host pre-load MemAvailable≥14GiB. Owned ASR GPUallocation≤4.5GiB including context, PyTorch allocator≤4GiB, global GPUfree≥1.25GiB while CORE32K remains loaded. Require≥6GiB GPUfree before ASR load. The new GPUbudget is not an increase to CORE VRAM or physical RAM caps. First run an offline no-weights CUDA initialization/matmul probe under this profile and record actual virtual/RSS/VRAM usage. Stop on OOM/resource/provenance failure; no cap escalation or precision fallback.

Before inference freeze all40original D72primary speech sources20VI/20EN and original labels, both ASRs and historical raw ungated CPUoutputs. One first GPU prediction per candidate/source:80ASRcalls, no retries. Inputs remain original source float bytes for this separate standalone comparison. Report exact transcript parity and every changed word. This is same-source historical-baseline comparison, not a contemporaneous CPUtiming experiment or unseen holdout; no relabeling/tuning/replacement after a failure.

Only qualified candidate lanes proceed to a fixed native group of the original six D74sources each: at most12turns/12VAD/8ASR/8CORE/8TTS. Keep all failed/unattempted rows. Native utterances are original-volume VI; quiet-ASR/real-room/general correctness remain separate.

Quality/native phases together≤1800seconds, existing per-turn180second and worker CPU/log caps, private outputs≤8GiB. GPU ASR and original CPUVAD/TTS coexist only within the aggregate guards. Use only exact owned processes; no preexisting CORE replacement, Docker/Vault/database/provider action or shared-service restart. On completion/fault/cancellation, join every worker and restore baseline. Rollback omits the optional CUDA execution profile; no migration/default cutover.

Each loaded ASR explicitly performs one1secondzero-waveform readiness inference before emitting ready, recorded separately with input/output hashes and duration. It contains no user data and produces no cached answer. At most4readiness calls across the2quality and2native loads, so total ASRbudget≤92(80quality+8native+4readiness); waveform/model/allocator initialization time remains outside submission and is reported, not labelled cold latency. A capped/failed readiness stops that lane; no hidden additional warmup or retry.
