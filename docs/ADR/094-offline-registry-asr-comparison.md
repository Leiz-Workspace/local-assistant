# ADR 094 Offline registry ASR comparison

**Purpose:** Define D68 controlled Qwen3-ASR-0.6B versus Whisper/faster-whisper evaluation and provisioning boundaries before candidate execution.

**Date:** 2026-10-22. **Status:** Accepted for existing D68 offline evaluation after D67 commit dd14a4a/full4495/final audit; no selection/deployment approval.

MODEL-EVAL-003/D68 is existing P2 registry work, now scheduled under the owner's continuous project implementation request. Dependencies: independent Vietnamese/English speech references, frozen common audio preprocessing/metrics, bounded local runtimes, D67 CORE/resource baseline and model/license/artifact verification. Effort1–2 provisioning/corpus/comparison milestones, separate from selection/production integration. Risks: unequal language hints/precision/threads, dataset/model training overlap, normalizer-driven score changes, incomplete coverage hidden by aggregate scores, missing silence hallucinations, CPU/cache/cold-load confusion, hidden forced-aligner/other-model downloads and treating downloaded candidates as approved defaults.

Plan total model+corpus storage about3.2GB plus isolated runtime/cache, budget up to6GB new files before execution. No private recordings, account/key or cloud transcription.

Before model predictions select first20 test.tsv rows per language in original order that meet common1–20second input/valid label requirements; preserve all excluded IDs/reasons. References come from upstream human-labelled corpus, not assistant-authored D66 speech text. Public benchmark/model training overlap is unknown; this small subset is not the official full FLEURS benchmark or general private-user accuracy. Add four declared no-speech requests (English/Vietnamese hints × same silence/seeded low-amplitude-noise waveforms); report two unique control waveforms separately. Inspect actual raw codec/rate/channels before normalization; never silently widen already accepted audio formats or change prior580/599 source to accommodate them. If corpus format needs new support, add an isolated evaluation-specific bounded decoder/protocol with real positive/negative tests and explicit version/provenance; production normalization remains unchanged.

Both models receive exactly the same frozen mono16k PCM-derived float32 waveform, source/PCM hashes/counts and text references, one actual prediction per case/no outcome-driven retry. No audio/text truncation; unsupported/overlong/failed cases are retained and incomplete coverage cannot support a winner. Freeze normalization before scoring: NFC/casefold, Unicode punctuation→space and whitespace collapse; keep accents/digits, no numeric/spelling/translation repair. Report raw predictions, per-case edits and per-language micro-aggregated whitespace WER and CER without whitespace, plus normalized nonempty false positives on known no-speech. Vietnamese whitespace WER counts orthographic syllable tokens, not certified linguistic words. Rates can exceed1 and are not probabilities. Retain raw/reference/scorer versions and all errors. Neither dataset provenance nor ASR output verifies word timestamps; Qwen word timing is NOT EVALUATED without an unapproved additional aligner.

Record that concrete engine value and Qwen's actual `torch.float32` parameter dtype in each observation. Both inference processes are restricted to the same logical CPU affinity0,1. Import/style and runtime-metadata qualification snapshots precede all common-corpus predictions; retain the initial prelint freeze and create a qualified paired freeze before either scored run, rather than overwriting an earlier snapshot.

Qualification clarifications before inference: primary Qwen prediction is raw official backend decoding, without the optional high-level SDK's repetition-repair helper; Whisper is the fully materialized raw segment text.
