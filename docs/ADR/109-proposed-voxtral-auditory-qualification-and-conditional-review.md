## Frozen controls and independence limits

The new private packet is `data/backups/d70-voxtral-local-reviewer/auditory-109-controls`: **12cases/18opaque float32 signals/20files**, fixed seed109 and full-file hashes. Two retained public FLEURS-derived sources, `en_us-0003` and `vi_vn-0003`, are bound to exact sample counts/digests in the parent controller. No new source download. They were not sent to the original Voxtral checkpoint in this project; this does **not** establish absence from pretraining or independent human naturalness annotation.

Presence: two speech recordings, authored exact silence and seeded Gaussian noise. Language: EN and VI. Comparison: four authored severe-defect orientations (gain40 followed by clipping; exact middle-half zeros) and two identical-pair ties. Expected comparisons are balanced first2/second2/equal2; presence yes2/no2, language EN1/VI1. These are predeclared corpus/transform expectations, not human MOS or broad subjective-quality gold. No D70 benchmark signal is used for these controls, and no candidate name, source identity, transformation, expectation, transcript or previous answer is mounted in the worker.

Require **12/12**, complete native EOS and parse/schema success, unchanged sources/runtime/model/packet, original tensor receipt equality, unchanged CORE and independently replayed conditioning. `UNCERTAIN` is retained and fails a factual control. Casefold and outer-whitespace normalization for closed control labels are declared **before any original Voxtral answer**; punctuation/prose/correction is rejected. Review requires strict JSON `{naturalness, notes}` with natural/unnatural/uncertain/not_applicable and1–40word notes; no code-fence repair, duplicate keys, numeric MOS or extra fields. Raw output/token IDs remain authoritative.

## Native conditioning and tested compatibility

Use only the prepared revision `3060fe34b35ba5d44202ce9ff3c097642914f8f3` and its existing CPU SDK. Encode full mono16k float32 samples as lossless FLOAT WAV in memory, then the pinned Mistral/Voxtral native chat template. No PCM16 quantization, resampling, normalization, crop or truncation. Native Mistral itself pads each recording to30seconds; verify the entire original prefix byte-for-byte and every added tail sample exactly zero. Feature extraction uses the original Whisper defaults/dither0,128mels/3000frames. The pinned projector/tokenizer emits **375audio placeholders per30second chunk**, not1500; two recordings emit750. Native input IDs are independently compared with the tokenizer path; bound the input at4096tokens by rejection, never truncation.

Retain source/padded-waveform, input-ID, FP32-feature and exact BF16-conditioning hashes. A second network-isolated **no-weights** process replays every first input/feature and must exactly match the original worker's receipt before competence/review is usable. Its mounts contain only tokenizer/preprocessor metadata and opaque signals; parent gold/request provenance remains outside both workers. First raw worker/replay/process receipts and complete source/packet bindings are rechecked before conditional common-audio access; a mutable success flag alone is insufficient.

Real SDK tests use only authored zeros/sine and a random **2,760parameter** native model. Processor tests cover all four prompts, single/pair signals, unchanged source prefixes, native padding and375/750token counts, with no original weight/recorded-audio mount. Tiny native eager/SDPA forward and two-token deterministic generation pass; observed logit difference0 on this fixture, all weight dtypes/bytes/pointers unchanged. This proves API compatibility, **not original-model accuracy, memory fit or an SDPA performance advantage**.

Keep original weights/load fidelity through the accepted pread loader. Then switch **only the isolated evaluator's native attention implementation to SDPA** and verify all payload hashes/pointers unchanged plus native audio/language/config flags. This addresses attention-allocation risk without reducing source/context or altering model weights. It is a proposed research-runtime change, not a production architecture/model change. Actual original SDPA audio memory and quality remain unmeasured.

Compatibility failures were caught before any original prediction: the first full-source hash comparison wrongly included legitimate native zero-padding; `audio_kwargs` is incorrectly forwarded by this pinned wrapper; direct tokenizer output initially used a different batch shape; and the first placeholder estimate ignored the native projector's factor4 reshape. Correct the caller/estimator using inspected native behavior, retain all failure logs, preserve SDK bytes and enforce source-prefix/tail/feature invariants. No observed model judgement was repaired or rerun.
