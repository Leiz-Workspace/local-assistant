# ADR 164 — Reading-policy bridge for voice workflows

**Purpose:** Connect the owner-accepted Trúc Ly speech preparation to the unchanged buffered VoicePipeline without losing original-answer provenance or reopening pronunciation refinement.

**Status:** Implementation and software/model-free validation authorized by the owner's “Làm đi” after the next-step plan. Product defaults, models, presets and the frozen ADR155 native campaign remain unchanged.

## Decision

Add research-only modules, leaving the750application/210protected and46previous research files unchanged. The existing VoicePipeline requires VoiceSpeech.text_sha256 to match the original CORE answer. A naive text-rewriting wrapper violates that contract. A research TTS bridge will retain the original answer, render a separate speech string through the exact accepted English-preserving date/clause renderer, require the backend's result to bind to that rendered string/owner/model/language, and only then return a VoiceSpeech bound to the original answer. Record both hashes and the exact render edits in an owner-controlled audit sink before publishing success. Never mutate the CORE answer, return truncated audio, accept a mismatched result or claim that changing only the returned hash verifies the speech.

The native Trúc Ly adapter reuses original punctuation-preserving chunking, generation, speaker/reference audit, sampling and joining. It uses only the retained API stress pattern with spaces and the three ADR160 Python/GitHub/server phone targets. The unaccepted compact Ngọc Huyền experiment is excluded. Replace no unknown words or I phones. Extend bounded exact-span planning to zero/multiple known terms in non-whitelisted CORE responses; require normalized lexical counts to match bounded whole-phone spans, reject ambiguous mappings before the first generation, and retain a min(original cap,reading cap,300) allowance. Build/check all chunks before generation. Do not rewrite protected code/URLs/identifiers containing policy targets or admit caller-supplied SDK phoneme/language controls; refuse unsupported text explicitly instead of guessing, silently dropping content or enlarging limits.

Use the existing Trúc Ly lane for this optional VI-first research composition, not product voice/model selection. Piper comparison and both ASR choices remain available unchanged. Backend profile/voice and source/rendered result identities must be checked. Single-operation admission stays occupied until dependency cancellation/cleanup joins; audit-sink failure, timeout, wrong capability or late result cannot publish a successful turn. Native waveform and playback conversion remain separate; no first-audible4second claim follows from buffered software timing.

## Validation and scope

Test the actual unchanged VoicePipeline with source-bound authored ASR, real gateway metadata mapping under mocked HTTP where appropriate, and controlled speech results. Cover original answer versus spoken hash, dates/questions/English terms, zero/multiple/repeated/ambiguous targets, protected identifiers, wrong owner/model/language/hash/audio/completion, negative transcript, timeout/busy/close, repeated cancellation and audit failure. Use existing no-weights SDK/tokenizer isolation to verify real normalized chunks/phones/caps and exact parity against the accepted ten-case Trúc Ly packet; do not synthesize new listening clips or load weights during preparation.

Priority P1 VOICE-LATENCY-AC-001 / D74 workflow preparation. Dependencies: accepted renderer/policy, original VoicePipeline/ports, fixed model/reference provenance and explicit trace binding. Effort one integration/test milestone, then a separately bounded native workflow evaluation. Risks include unsupported arbitrary CORE text, phone-count ambiguity, incorrect result rebinding, cleanup races and confusing a proxy with device playback. Rollback removes only the optional composition and retires its owned dependencies; original source/defaults/artifacts remain unchanged. No downloads, new model/reference, service/Vault/database/Docker change or product endpoint activation.

ADR155 remains locked and historical; its old48slot plan does not acquire a new reading policy implicitly. The prepared integration must be bound into a concrete revised native scope before dispatch. D60 remains owner-deferred; D74 physical4second/rights/no-speech/product/D90release stay open.
