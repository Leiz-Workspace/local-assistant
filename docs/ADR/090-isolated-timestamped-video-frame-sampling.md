# ADR 090 Isolated timestamped video frame sampling

**Purpose:** Define D64 reproducible FFmpeg media metadata/frame provenance without selecting a standalone video or speech model.

**Date:** 2026-10-22. **Status:** Accepted for local explicit-byte adapter after D63 acceptance.

Existing D64/P1 depends on D61 private image normalization and D62 synchronized native input. Effort one bounded video contract/isolated worker/parent adapter plus real CFR/VFR goldens and lifecycle tests. Risks: treating requested time or frame-index/fps arithmetic as decoded time, nonzero/VFR origin errors, malformed containers/resource expansion, external protocol reads, unnoticed audio or attached-image streams, raw frame persistence, writable input FDs and releasing children before cleanup. No accepted code change is planned; reuse its readonly payload/PID/network namespace boundary.

V1 accepts only explicitly supplied immutable bytes1–32MiB and1–3 unique increasing integer millisecond targets0–30000. No path/URL/HTTP route/history/automatic recording. The native worker exposes the existing readonly /payload, never a writable/reopenable host source. Restrict demuxers/protocols to local Matroska/WebM or MP4 families; one nonattached video stream, at most one audio stream, no other stream types; duration at most30s, long edge at most1920px/2073600 pixels and decoded frame count at most900. Bound metadata/decoded-frame JSON and every PNG. Audio metadata includes codec/rate/channels and its own rational time base/startPTS; missing start stays null, never guessed zero. These are container clocks, not speech alignment or a certified sample-accurate audio timeline. Audio metadata is reported explicitly; no waveform/transcript extraction, ASR selection or microphone consent implied.

Probe the actual integer best-effort presentation timestamps and rational time base; require strictly increasing PTS. For each relative target choose the first decoded frame whose (PTS−firstPTS)×timebase is greater than or equal to the target; reject targets beyond the last decoded frame. Preserve target separately from actual PTS, origin, index and exact relative rational numerator/denominator. Never compute actual time from average FPS, fabricate timestamps or silently duplicate a last frame. FFmpeg selects the corresponding decoded frame index from the same immutable source with autorotation disabled; normalize pixels in the isolated worker to metadata-free RGB PNG at most1280px/1MiB per frame. The duration field is explicitly container-reported and may include a nonzero start offset; decoded relative time always uses first-video-PTS, not that container duration. No broad timestamp accuracy beyond supported validated streams/first-video-PTS origin; rotation/display-matrix editing is out of scope and exposed as a limitation.

Use fixed commands, no shell/user codec/filter/backend arguments, one decoder/filter thread, existing credential-free network/PID/mount namespace and readonly filesystem. Worker caps512MiB address space,8/9CPU seconds per process,32FD,8MiB output and no core dumps; complete parent deadline40s, child deadline8s. Source/anonymous output FDs stay owned until native exit/timeout acknowledgment; metadata-only logs and finite errors. Parent validates complete duplicate-free bounded JSON, source hash, rational time consistency/order/target correspondence and canonical PNG bounds/CRCs without host pixel decoding. Workers own decoding/normalization; caller receives frozen typed metadata/frames with untrusted provenance, never a tool/action receipt.

Acceptance: actual deterministic repeat produces identical frame hashes and timestamps on an authored audio-bearing CFR clip; genuine VFR/nonzero-origin tests prove decoded PTS rather than index/fps estimates; malformed/unsupported/oversize/range/schema/timeout/no-leak/no-source-mutation tests; current prior569 source/model/config/data/security/runtime remains unchanged. Native FFmpeg versions/build and frozen source hashes are recorded, no package/model/image downloads. D65 consumes these frames through original CORE, D66 audio integration must respect actual ASR dependency rather than inventing transcripts. Authenticated file/API/UI delivery remains separate VISION-PROD-001 work before production.

Rollback drains/removes only new local video operations/adapter/evaluation files, retaining every original file/blob/database/model/config/service and prior result. No default route, accepted OCR/image behavior or model selection changes.
