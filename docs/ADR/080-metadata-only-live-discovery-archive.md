# ADR-080 — Metadata-only live discovery archive for the D60 gate

**Purpose:** Keep restricted actual provider snippets out of durable artifacts while evaluating original live discovery, signed primary excerpts and complete report/export archives.

**Date:** 2026-10-21. **Status:** Accepted for the bounded D60 evaluator; no production API or accepted D59 source change.

D60-T03 committed590a8a5 after official runtime review,13 original native PASS and readonly audit. All536 accepted source/config files remain unchanged. Original D59 session facade archives the complete D54 result, which includes source titles/snippets; its actual acceptance used authored empty provider batches. D60's live-provider evaluation requires metadata-only retention under ADR-079. Do not silently reuse that full-data archival behavior for actual restricted provider content or modify accepted D59 components without necessity.

## Decision

The D60 test/evaluation-only composition uses accepted ResearchService/ResearchReportService/ReportExportService and PrivateResearchSessions directly. Reserve discovery in the original durable two-stage journal before one actual CORE plan/at mostthree selected-provider queries. Keep complete actual query/source results in memory only; archive an explicitly labeled metadata projection retaining complete per-query status/attempt/error/UTC/IDs, URL and original query/title/snippet hashes. Mark raw provider payload not retained. No fake complete-result or lost-data guarantee for never-admitted restricted content; preserve every authorized metadata/primary excerpt/report/export byte. No parser/source/model/provider/config/service/Vault/database change.

Choose at mosttwo source URLs using a host-owned frozen primary host/path family whitelist and original query/rank ordering. Every chosen original URL must actually occur in a valid search result and pass unchanged D49 URL/DNS/TLS/redirect policy; final host remains in the expected primary family. No exact search hit is invented for a separately caller-designated URL, no canonical alias or source fallback and no network request if a required source family is absent. Such a missing source keeps the actual gate failed/partial with original outcomes retained. No automatic retry/provider/engine rotation or CAPTCHA/suspension bypass.

Fresh primary acquisitions use original source provenance/proofs and short predeclared exact start/end-marker spans, at most25words per quoted primary excerpt. Bounds are explicit excerpt selection, not silent output clipping; missing/ambiguous/oversized spans refuse. Assess three predeclared supported/contradicted/insufficient claims with one original CORE completion, generate complete D57 Markdown and one original D58 DOCX/PDF batch. The report/native files include the complete selected excerpts/claims/reasons/unknowns, not full raw pages. No report receipt/proof key/monotonic deadline is persisted. Reopen completed owner-bound archive bytes after all live issuers revoke; this does not revive live authorization or verify current freshness. Final artifacts require all-page visual QA.

Use fixed two-stage once-only reservations and original storage inode/owner/hash/fsync/lock/no-eviction limits. The evaluator's publish sequence explicitly bounds source reads≤two/30s total plus report/native≤50s, outer90s cooperative deadline and joined cleanup, without changing the D59 service's60s limit or claiming this evaluator is that facade. Runtime-owned clocks are real for actual live source/report/export work. No arbitrary user command/path/format/tool budget, background loop, secret/private-context access, extra drafting model call or production provisioning. Failure/interruption retains original attempts and authorized bytes; no automatic replay.

## Assessment and follow-up

P1 before live provider/session API adoption; depends on D54–D59 and the original selected provider rights/privacy scope. Estimate one narrow metadata policy/evaluator/negative ownership/source-selection test and actual phase trial; runtime-reusable retention policy remains separate. Risks: accidentally persisting restricted snippets, pretending hashes preserve retrievable raw data, trusting returned URLs/canonical claims, weakening original source admission, or conflating low-level store composition with production session facade acceptance. Record original D59 full-data behavior as authored/local only pending explicit provider-retention policy qualification.

Future live session facade adoption must evaluate provider/result-use rights, explicit data classification/minimization/retention, owner authentication/encryption/access/audit/deletion and finite recovery limits. PriorityP1, dependency provider contract/operator storage policy and D59/D60 frozen corpus, effort one policy/adapter/qualification milestone; risks disclosure, unwanted retention, content loss or unauthorized durable action. No adoption/model/dependency/service change is authorized here.

Rollback removes only the new evaluator/pure policies and drains trial-owned model/source/native/store handles, retaining all first outcomes/archives. Original D59 source/API/services/provider/model/data/containers/Vault/database remain untouched, no migration/reindex.
