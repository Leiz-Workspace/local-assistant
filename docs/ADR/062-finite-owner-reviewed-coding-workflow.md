# ADR-062: Finite owner-reviewed coding workflow

**Purpose:** Define D43 issue→plan→diff→approval→checks→summary composition without replacing accepted model choices or making generated text an action capability.

**Date:** 2026-10-20 (Asia/Ho_Chi_Minh)

**Status:** Accepted and verified within D43 local finite reviewed workflow scope:1190 related PASS/72.99s plus separate first actual CORE sample1 PASS/4.61s,0SKIP/exit0;87 new cases,405 source/434 protected hashes and clean audit. [Acceptance](../evidence/d43-workflow-acceptance.json). D42 historical full2461 remains separate; no new full/model replacement/production action claim.

## Priority, dependency, effort and risk

D43 is the existing P1 next milestone, depends on accepted D33–D42 scope/reads/checkpoints/exact approvals/native checks. Estimate one finite workflow milestone plus contract, native service, HTTP/CLI/cancellation and actual unchanged CORE sample-repository acceptance. Risks: treating a generated plan as approval, source/context drift, cross-owner references, attaching a different approved patch/check, losing applied results when a later step fails, conflating exit0 with quality, and implicit retries. No new model/package/dependency/infrastructure/database/Vault change is proposed.

## Proposed finite composition

Use the existing CORE/fast profile without changing model configuration. An authenticated owner explicitly supplies a bounded issue, one existing eligible Python target, its expected raw SHA256, selected immutable test paths/hashes and one existing D42 profile. Read only these selected files through accepted native capabilities; refuse source/prompt overflow before generation. File/command/profile/root/model/resource scope is server-owned. No autonomous repository discovery, shell, dependency install, extra file, model-selected path or command.

The model returns only a bounded manual plan plus one complete replacement for the fixed target. Validate an exact JSON schema, full UTF-8/no-NUL size, syntactically valid Python and English description requirements before proposing an edit. It is untrusted generated content; do not import/evaluate it on the host. Plan text has no tool/action authority. Revalidate the original complete selected source context after generation and before creating the D41 checkpoint-backed patch proposal. Preserve every invalid/incomplete/failed model attempt; no repair retry/score selection.

A trusted finite service retains owner/workspace workflow ID, immutable issue/context hashes, model attempt status, generated untrusted plan, concrete patch/check IDs and actual known receipts. Bound active/history counts and total retained bytes explicitly before implementation. Records are process-local; durable checkpoint/check history remains separate and does not reconstruct workflow/grant authority after restart. New API enablement is separately default-off and requires live accepted dependencies.

Final first limits before implementation: one target plus1–3 distinct selected test files, existing D42 per-path/per-file limits, at most32768 source bytes and32768 complete prompt UTF-8 bytes; issue<=2048 UTF-8 bytes. Reject prompt overflow before inference, without truncating source. CORE/fast/temperature0/max_tokens2048,60s joined generation, no retry; exact model JSON keys `plan` and `replacement`,1–5 nonblank plan strings<=512 UTF-8 bytes each, complete replacement<=8192 raw UTF-8 bytes and raw completion<=16384 bytes. Count16 retained workflows globally/4 owner, no eviction, at most128KiB canonical public/attempt/result data per workflow/2MiB total records. Component native/durable quotas remain unchanged and independently enforced. Retain failed/cancelled attempts in the same counts. Each pending patch/check still has its own120s lifetime; no workflow deadline extends it.

First response contains the complete D41 diff/review and pending patch approval; no edit or program runs. The owner reviews/types the exact existing CLI request UUID and separately invokes the workflow's explicit apply endpoint with that linked UUID. Use the unchanged D41 apply path; no second hidden approval store or bypass. Reject foreign/wrong/replayed/expired/changed-source grants before mutation.

Only a known applied receipt may proceed to capture tests. Bind the target's exact new SHA256 from that receipt plus the originally selected test hashes. D42 creates a new concrete pending `run_checks` artifact for the immutable updated snapshot; a patch grant never approves execution. The owner separately reviews/types this second UUID and explicitly invokes run. No automatic program after edit, proposal, approval decision or summary read.

Wrong/unapproved UUID precondition denials must leave a valid pending stage inspectable so the owner can still review it. A stage becomes attempted only after its actual linked approval preconditions pass. Once admitted, native/source/persistence failure does not authorize another action attempt. Component approvals remain independently owner-bound; cancelling a request/workflow is not a claim that a separately approved component grant was retroactively revoked. D44 must define any broader pending-action revocation/cancellation semantics explicitly.

Prefer explicit separate apply/propose-checks/run-checks transitions over a monolithic request: failure after a committed edit must retain its actual receipt independently of later capture/model/response failures. Each stage has at most one attempt in D43. State, receipt and uncertainty survive caller cancellation/lost acknowledgement in memory; use existing durable component inspection after restart, with no automatic resume/refund/rollback. Later retries/hooks/feedback require D44 ceilings and new context/approval.

## Truthful summary and lifecycle

Build summaries from trusted component receipts, not a second model claim. Distinguish planned/proposed/approved/applied/uncertain/check-not-run/native-exit/failed/cancelled. Include source/version/checkpoint/approval/check IDs and hashes, actual command observations and limits. `quality_evaluated=false` remains the general native result. Printed test markers/exit0 cannot approve a patch, grant a command, select a model or assert general correctness.

Bind a check observation to its captured source version/target SHA256, separately from the historical applied receipt. Another cooperating owner operation may later edit the workspace; finishing an isolated snapshot does not establish current live workspace bytes. Summary must not claim the current workspace is fixed or unchanged unless independently observed for that claim. Expose the tested snapshot version and `current_source_observed=false` from the native contract; the host-authored sample acceptance separately inspects its final controlled source/test bytes.

Authorize owner/workspace before record lookup, expiry or side effects. Reject normal overlapping operations without queuing. Track/join generation, native capture/write/check work and owned source pins through cancellation/shutdown. Drain workflow service before checks→checkpoint→approval→workspace. Existing tools, finite domains and accepted source code should remain unchanged except necessary router/lifecycle wiring.

## Proposed acceptance

Freeze a new small sample repository/issue/oracles before actual CORE inference. A complete local TCP workflow must use actual CORE once, show plan/full diff, require two separately typed concrete fixture approvals, apply a checkpoint-backed single-file edit, run actual isolated stdlib checks, retain source/checkpoint/native results and emit a truthful summary. Verify the sample functional property with a host-authored bounded structural oracle plus fixed trusted native tests; this is a visible sample workflow demonstration, not an unseen model benchmark or replacement of D38's immutable4/6 baseline.

Pre-inference sample: [`d43-visible-sample-case.pending.json`](../evidence/d43-visible-sample-case.pending.json), SHA256 `2153fba8d61b1d5cc2cda3f980a388a567cdddbd3634500e45e72ae216607075`. The fixture changes exactly a documented integer sum's subtraction operator to addition, keeps audit/source structure and fixed tests unchanged, and freezes four host-authored input/expected pairs. Keep its planned_not_executed label unchanged as pre-inference provenance; [actual first observation](../evidence/d43-core-live.json) is separate:1 original CORE attempt, two typed fixture approvals, structural oracle and four native assertions PASS. Actual candidate formatting differs from reference bytes while the frozen AST gate passes. This is a visible authored sample, not an unseen benchmark, human-independent proof or replacement for D38.

Test invalid/truncated/model-output injection, ignored source/issue instructions, extra fields/paths/commands, source/context changes, wrong owner/linked grants, absent approval, changed selected tests, replay, expiry, busy/cancel/shutdown, failure after edit before checks and lost result delivery. Keep every failure and avoid repeated inference to select a passing score. Run affected D33–D42/API/lifecycle regression and readonly security/model/config/data audit. Use the accepted D42 full as the immutable baseline, run affected D33–D42/workflow/API/lifecycle tests plus the separately retained actual CORE sample and readonly audit. New workflow code and necessary router/lifecycle wiring require these related/composition gates; if shared native/security/model/source semantics change, run a new exact-source full. Never call a collection/related run a fresh full.

Conditional pytest/packages, larger/multifile edits, durable workflows/cross-worker grants and automatic recovery remain [assessed backlog](../CODING_AGENT_BACKLOG.md), not implicit extensions. D44–D46 retain their own acceptance gates. All fixture approvals are explicit trusted test actions, never production action permission.
