## New unwired adapter

Add a separate `SearxNGSearchAdapter`, with default `instance_reviewed=False`. No modification to the accepted search port/pipeline/Brave adapter/model routing/startup. Fixed endpoint `http://127.0.0.1:8889/search`, no client/model/URL override, redirects, environment proxies, credentials, retries, page fetching or persistence. Direct construction makes no request; review is a trusted operator configuration condition, not a client-supplied grant. Fixed public engine set and page1; explicit query only, languageauto, JSON form POST. No query in request URLs/default HTTP request logs.

Total10second cooperative deadline; raw identity-encoded JSON only, max128KiB/8192byte reads. At most50 raw result rows; reject malformed shapes, query mismatch, malformed upstream-failure lists, body/row limits and **any** invalid result, including rows outside the selected window. Ignore provider answers/suggestions/infoboxes as answer authority. Validate every row through the accepted hit bounds and HTTPS link representation. A present upstream-failure list is preserved as finite count in metadata; an empty result with upstream failures is unavailable, not an ordinary no-sources success.

SearXNG has no documented result-count request parameter. Therefore explicitly project the first five validated rows, preserving provider wire order, and log received/selected/omitted/failure counts only. This is declared bounded retrieval, not a complete result set or reranking. The returned immutable five-hit port response is still validated in full by the unchanged pipeline. No silent row clipping, field truncation, query changes, invalid-row skipping or model-selected result selection. The projection differs from the Brave reference's requested five wire results and must be disclosed in actual evaluation.

## Observed upstream incompatibility and necessary repair

First real frozen trial returned HTTP200/ten rows but irrelevant selected sources; CORE correctly refused, failing the predeclared answered/JSON/primary-citation oracle. Retain that first failure and exact full source archive. Four zero-model diagnostics retained variable relevance, a DuckDuckGo CAPTCHA and Wikipedia suspension. Their form included categories: pinned [parse_generic](https://github.com/searxng/searxng/blob/81371861f67226091d1c4df2e3908a11d3b54eb9/searx/webadapter.py) adds category engines to an explicit engine list, so the panel does not isolate engines. No per-engine relevance score is claimed.

Remove categories from the adapter, limit the owned instance and adapter to the official Google engine, and validate every raw row's engine/merged-engine provenance against that singleton. The initial engines remain unqueried; no CAPTCHA bypass/proxy/secret manipulation. One new bounded compatibility/source-provenance milestone, P1 dependency before live acceptance; risks are upstream HTML/API drift, single-upstream availability and overfitting one visible smoke query. No Google API key, paid service, model replacement, resource widening or source/model-threshold relaxation. Existing D47 accepted services/prompt/model remain unchanged. A separate fresh source freeze and one-attempt live verification follows; original failed first trial and diagnostic limitations remain visible. Google website terms/upstream rate limiting still apply; no universal API/SLA/storage-rights or general relevance claim. D53 coverage/freshness remains future work.

Google-only repaired-source live request returned HTTP200/zero rows/one upstream failure, before any model call; a subsequent zero-model diagnostic observed suspension. Retain this second failed cohort unchanged. No further Google/DDG/Wikipedia calls, CAPTCHA bypass or public-instance rotation. A predeclared two-engine zero-model compatibility panel considers Mwmbl and Brave frontend, one fixed public query each with explicit selection and no category expansion; choose the first ready engine under frozen order/criteria, recording both results. Pinned source inspection rejected Mojeek before execution because it contains automatic CAPTCHA-solving code. This panel measures one connection/query sanity case, not general ranking superiority; raw results are not durably stored and no model score is selected. Both prior failed cohorts remain required evidence.

## Final selected upstream after the frozen compatibility panel

The two-engine zero-model panel returned Mwmbl HTTP200/eight rows without the required primary domain in the first five, and Brave HTTP200/twenty rows with docs.searxng.org present, exact query and only the selected engine. Frozen order chooses the first ready engine, **Brave frontend**. Keep only that engine in the instance and adapter; other engines are not hidden fallbacks. This is SearXNG's anonymous website engine, not Brave's API/key/paid plan and not another model. [Pinned engine source](https://github.com/searxng/searxng/blob/81371861f67226091d1c4df2e3908a11d3b54eb9/searx/engines/brave.py). No Mojeek request was executed. The panel is connection/query sanity on one visible query, not a broad comparative relevance benchmark; D53 remains required.

Run fresh82 fixture/provenance tests and a separate final-source actual acceptance with the **unchanged original query/oracle** and one call per stage. Preserve both previous live failures, their exact source/config archives, Google suspension and all panel outcomes; no relabeling of original attempts or model score selection.
