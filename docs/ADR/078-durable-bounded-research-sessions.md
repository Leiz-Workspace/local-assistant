# ADR-078 — Durable bounded research sessions and explicit boundary resume

**Purpose:** Define restart-safe progress, retained artifacts and cancellation ownership for D59 without reviving expired evidence or automatically replaying uncertain tool calls.

**Date:** 2026-10-21. **Status:** Accepted for implementation within an unwired local, exclusive private-store scope; acceptance requires real tests.

D58 is committed at7f9dd18e984c49edee99e2f1deb722a126ebb38b with2504 related PASS/0SKIP, actual both-format export/all-page review and clean audit. All522 accepted source/config bytes remain baseline. D57 receipts and D51 source proofs are process-scoped and expire; a persisted dataclass/hash is not future authorization. No model/API/Docker/Vault/database/config/dependency or existing data changes are required.

## Decision

Add a finite two-stage session service around accepted D54 planning and D57/D58 report/export. Stage discover performs one bounded D54 plan (one CORE and at most three sequential provider calls). It durably archives the complete result and pauses. An explicit owner advance, supplied fresh D51 signed spans, performs publish: one D57 assessment/report followed by one D58 native export, preserving a durable draft checkpoint before native work and complete both-format artifacts after it. No automatic stage loop, URL selection from model output, background retry, polling, fallback or arbitrary tool/command is introduced. One session can reserve each stage at most once; at most two model completions/three provider calls/one native batch through these components. Existing quotas remain additional bounds, not durable cross-process global billing.

Use an explicitly provisioned existing0700 private filesystem root outside registered workspaces, exclusive process flock/nonqueued store lock, using the accepted PrivateCheckpointRoot native guards unchanged. Require a trusted server-owned workspace catalog, root/file native identity, single-link owned0600 regular files, no symlink/mount traversal. No default directory creation or production provisioning. Root lifetime excludes another worker; this is exclusive failover, not distributed multiworker service. The process UID/operator and local filesystem remain trusted; hashes detect corruption, not compromise of the owning UID. No persistent signing key or receipt is introduced.

Each UUID run directory contains a bounded strict32KiB journal and immutable discover/report/export blobs. Journal includes exact owner, normalized goal/claims, finite state, original attempts and complete referenced artifact hashes/lengths. Write/fsync the attempt before any async dispatch, then immutable output file+directory, then atomic fsynced journal publication. Reserve discover/publish once, without refunds. Max16 retained sessions/four per owner, no eviction; discover128KiB/report256KiB/export9MiB, bounded per-directory entries. Capacity exhaustion refuses new work and preserves earlier data. No user-controlled filenames/path, append-only arbitrary history or unbounded artifact creation. Synchronous local filesystem operations have bounded bytes; no hard I/O-latency or power-loss guarantee beyond host fsync semantics.

Ready→running discover→paused→running publish→complete. Interrupted/error is terminal for that session; do not reset counters or replay an ambiguous in-flight model/provider/native operation. Persist an explicit finite interruption after joined caller cancellation/deadline/error; repeated cancellation waits for owned cleanup before releasing admission. Shutdown joins only session-owned callers; shared planner/report/evidence/export/model/provider lifetimes and store closure remain externally owned. Uncertain cleanup/storage publication poisons admission. Native output cleanup remains D58-owned.

Explicit recovery marks previously running journals interrupted, retaining every acknowledged output, draft and bounded unreferenced candidate/temp file without promoting it to a committed artifact or deleting it. Malformed/unsafe/unknown storage fails closed and is retained for operator review. Recovering paused discover output permits the next publish only with newly authenticated source spans; the old archive is never parsed as live proof or executable tool instructions. A completed report after interrupted publish remains readable as an untrusted archive, but cannot authorize export after issuer death/expiry. Finish already committed exports can be read after restart as archived bytes with original provenance/unknowns; retrieval does not claim source revalidation/current freshness. No automatic rebuild or receipt lifetime extension. Manual recovery/retry of an interrupted tool needs a separately evaluated future policy.

## Priority, dependencies, effort and risks

D59 P1 depends on D54/D57/D58 actual gates. Estimate one finite state/storage/service implementation, real subprocess SIGKILL/fsync-window/lock/tamper/cancel/restart tests, frozen original CORE→pause/reopen→fresh-span report/export and related regression/readonly audit milestone. Risks: owner leakage, ambiguous durable writes, orphan candidates mistaken for completed output, retry budget reset, process lock/root replacement, stale proof revival, loss of prior bytes on cancellation, hidden tool loops and oversized archives. Tests must retain first failures and verify complete byte/hash identity, zero automatic calls during recovery and all owned resources joined.

All prior522 source/config bytes and source/data/service/model choices stay unchanged. New APIs remain unwired. Broader concurrency, encrypted/remote artifact storage, retention deletion, interrupted-stage retries and production packaging require explicit priority/dependency/effort/risk evaluation, not silent scope expansion.

## Acceptance and rollback

Require actual controlled/native process tests of clean restart, exclusive lock release after SIGKILL, persisted attempts before dispatch, successful boundary resume with fresh proofs, mid-stage terminal interruption with retained draft/output, no hidden replay, owner/tamper/unsafe storage/size/capacity/dispatch/timeout/repeated-cancel/shutdown gates. Freeze first original CORE integration inputs/oracles before scoring, distinguish authored provider/source fixtures from public research and labels from semantic truth. Related regression and readonly source/model/database/container audit precede D59 PASS/D60. D53 quality/null freshness and existing before-D60 follow-ups remain open.

Rollback drains session-owned tasks and closes only its exclusive store handles; preserve private journals/artifacts and original component lifetimes. Remove the unwired facade/store/policies without model replacement, migration/reindex, Vault/database/source-data mutation or service restart.
