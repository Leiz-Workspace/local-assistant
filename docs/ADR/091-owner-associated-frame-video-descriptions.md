# ADR 091 Owner-associated frame video descriptions

**Purpose:** Define D65 bounded local frame descriptions with source/decoded-time provenance and joined cancellation before implementation.

**Date:** 2026-10-22. **Status:** Accepted for local explicit-byte composition after D64 acceptance.

Existing D65/P1 depends on D64 immutable timestamped frames, D61 private original CORE image questions and D62 native input repair. Effort one async composition service, immutable reply, lifecycle/negative controls and frozen actual three-stage description with ordinary-text recovery/readonly audit. Risks: permitting generated timestamps to replace decoded PTS, claiming continuous motion or audio facts from sparse images, partial-result confusion, quota amplification, mutable/mismatched dependency output and losing a running native thread/inner vision operation on repeated cancellation.

A new service admits one UUID owner, immutable explicit video bytes, validated1–3 millisecond targets and one bounded explicit visual question. Deadlines reject late results and cleanup acknowledgment may outlast a caller deadline. Cancel/shutdown joins only this service's owning work, leaving shared sampler/vision dependencies and unrelated tasks intact.

Revalidate the entire typed sample through D64's strict contract/source SHA before any model disclosure. Each frame is sent as a private explicit PNG question to the unchanged D61 service/original CORE. Validate returned owner/source/question/model/unverified metadata; attach requested time, actual decoded PTS/index/relative rational time and PNG SHA from the frozen host frame, never model-generated text. Answer frames remain untrusted/semantic-validation false/confidence null/unpersisted; failed later frames yield no successful partial clip response. Reject cancelled, timeout-suppressed or late dependency results before starting another frame or publishing. No automatic retry, interpolation, continuous-motion claim, speech transcript or synthesized temporal summary; audio remains metadata only. Anonymous temporary file closure is not certified memory erasure or server-side model abort.

Acceptance includes successful complete source-bound timestamped descriptions, invalid owner/input/port/reply and quotas/busy/late/partial-result denial, real controlled-thread repeated cancellation/shutdown lifetime, distinct actual original-CORE READY/MOVING/DONE source fixture at relative0/1/2s, ordinary text recovery and unchanged prior576 source/config/model/data/runtime audit.
