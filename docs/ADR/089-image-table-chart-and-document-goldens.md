# ADR 089 Image table, chart and document screenshot goldens

**Purpose:** Define D63 authored visual-functionality acceptance before observing original CORE answers.

**Date:** 2026-10-22. **Status:** Accepted for local evaluation after D62 full4265/final audit; no model/runtime/API changes.

D63 is existing P1 roadmap work, dependent on D61 normalized private image questions and D62 native handoff/quality acceptance. Effort one authored corpus, oracle tests, four actual questions, ordinary text recovery and read-only closure milestone. Risks include scoring a list of unrelated numbers as correct field association, rewarding guessed missing chart periods, confusing an authored screenshot with a live computer observation, leaking real documents and treating visible same-agent labels as independent/general semantic accuracy.

Generate three public authored fixtures using existing Pillow and installed DejaVu fonts: a January10/February30/March20 bar chart; a Vietnamese table with Bút quantity3/unit12000 and Vở quantity5/unit18000; an Atlas document dashboard screenshot showing release2.4, Files12 and Ready. No external image, personal screenshot or model-generated fixture. Visually inspect all three before inference and freeze their complete bytes, generator/fonts, questions, required/forbidden patterns and permitted numeric values before actual answers. One chart question asks maximum month/value; a second asks an absent April value and requires explicit abstention plus uncertainty/no numeric guess. Table asks only Vở quantity/unit price. Screenshot asks only release/file count. Four questions use one owner within the original quota; one ordinary text completion follows. One attempt per question, no automatic retries.

The scorer checks full NFC/case-insensitive response text against predeclared associations and rejects any numeric value outside that question's declared answer set. It never rewrites an answer, truncates tails, removes unsupported numbers or infers absent fields. Unit tests include reversed rows/months, swapped field associations, unsupported extra numbers, missing/guessed April and required uncertainty. Schema/source/owner/model/cleanup gates stay separate from functional scores. Preserve first failure and exact frozen evidence before any necessary generic repair; no fixture-specific prompt values in application code.

Use only existing VisionChatService/CoreVisionChatAdapter/NativeImageNormalizer and original qwen3.5-9b-core/mmproj/options/limits. No source, model, package, Docker, Vault, database or API configuration replacement/download. The generator decodes no untrusted input; actual image processing stays in the accepted isolated normalizer. Retain authored questions/answers for evidence, not raw model prompts/raster payloads. Answers remain unverified, review-required, confidence null and ephemeral; no receipts/tool permissions/action authority. D63 acceptance needs every declared functional golden, normal text recovery, joined native/HTTP/admission cleanup, relevant tests and final unchanged562-source/model/data/runtime audit. The current4265 global suite is the prior accepted source baseline, not a new full count for added D63 helpers.

VISION-PROD-001 remains a separately assessed authenticated file/API/UI integration milestone; D63 golden success does not activate it. MODEL-EVAL-006 alternatives remain conditional and require the user's benchmark/resources/migration/rollback approval rule.
