# ADR-027 — Owned DOCX inspection and run-preserving rewrite

**Purpose:** Define D19 read/write fidelity, source authorization and output ownership before implementation.

**Date:** 2026-10-18
**Status:** Accepted for localhost/one worker: 37 processor/contract/resource/opening and 16 DB/HTTP/lifecycle cases; final full 529 passed in 43.90s, zero skipped. Runtime lxml 6.1.3, dev-only python-docx 1.2.0; actual LibreOffice opening verified.

P1 work depends on D17 ready/namespace/owned FD isolation and D18 provenance conventions. Estimate one or more milestones. Risks include OOXML expansion, external relationships, XML entity loading, loss of run/table/style data, edit ambiguity, deletion during work and unbounded output. Runtime lxml preserves namespace declarations while editing XML; python-docx is a dev-only independent open/round-trip oracle. uv locks both. No new service, schema or credential is required.

Add authenticated `POST /files/{id}/docx/read` and `POST /files/{id}/docx/rewrite` under the existing local API. Read returns untrusted paragraphs/runs, tables/cells, explicit style IDs/direct run formatting, source UUID/hash and processor version. Paragraph/run indices are one-based in document order, not rendered pages. Includes main-body descendants; headers, footers and other package parts remain preserved but are not extracted. No calculated style inheritance, Word pagination, arbitrary visual fidelity, OCR or implicit model context is claimed.

Rewrite requires source SHA-256 and 1–100 unique `(paragraph_id, run_index, text)` edits, in a strict JSON body at most 64 KiB. Text supports Unicode, tabs/newlines and XML-valid characters. Replace only text/tab/break nodes of selected direct runs, retaining run properties, paragraph/table/style nodes and all other members. Refuse paragraphs containing non-plain structures (fields, drawings, hyperlinks, tracked changes, bookmarks, page/column breaks or unsupported children), missing indices, signed packages and ambiguous duplicate edits. Empty runs can receive text; no new paragraphs/tables or arbitrary XML/paths are accepted. Unedited runs and package members remain unchanged. Original bytes stay immutable.

Return a bounded DOCX attachment with source UUID/hash, processor version and output SHA-256 headers, private/no-store and nosniff. Output is ephemeral, never inserted into the journal or cache, and does not consume persistent file quota. A caller can use the existing reserve/upload flow to persist it under normal quota/verification. Any future automatic persistence needs a separate lifecycle decision.

Keep owned source SH FD through parsing, post-operation hash/ready recheck and cancellation joins. Two DOCX operations/responses per service, no waiting queue, excess 429; retain the slot, active task and shared source FD through complete response delivery or cancellation so slow clients cannot accumulate unbounded completed outputs; PDF retains its own two-slot gate. This is process-local one-worker admission. Reuse D17 Bubblewrap mounts/network isolation. Source enters stdin; a bounded anonymous edit-plan FD becomes a fixed read-only `/request.json` using `--ro-bind-data`. No document text, filenames or keys in argv/env. Source/root/auth/Vault paths are never mounted.

Worker applies 512 MiB address space,5/6s CPU,10s parent wall,32FD,zero core and25 MiB stdout before parser import. D17 OOXML verifier bounds/rejects active/external/DTD/archive content before lxml, with resolve_entities/load_dtd/huge_tree disabled and no_network enabled. Main XML remains at most 2 MiB, output file25 MiB, read JSON8 MiB, extracted text1 MiB, per-run text64 KiB,10000 paragraphs/cells,20000 runs,1000 styles. Reject overflow, never truncate. Rewrite output is reverified before release. Parent validates exact read schema/indices/budgets or bounded ZIP output; worker errors are allowlisted and diagnostics/text stay out of logs.

Acceptance: golden styled Unicode/multi-run paragraphs, table cells/merges, untouched members; exact edits with independent python-docx reopening; actual LibreOffice opens/converts trusted rewritten golden; malicious/unsupported/limits and sandbox/kernel/error cases; real DB/HTTP owner/namespace/hash/state/cancel/delete/admission negatives; full Vault-backed regression. Rollback drains operations and removes DOCX endpoints; source journal/blobs/auth and earlier milestones remain intact.
