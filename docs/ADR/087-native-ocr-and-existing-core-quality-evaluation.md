# ADR 087 Native OCR and existing CORE quality evaluation

**Purpose:** Define D62 measured native-first OCR/CORE VLM tradeoffs and hallucination indicators before any optional OCR/VLM replacement proposal.

**Date:** 2026-10-22. **Status:** Accepted for evaluation only after D61 commit0e39e99; no model choice/change/download or application implementation change.

P1/existing D62 depends on D18/D21 source goldens, D61 local normalization/image chat and original CORE/mmproj. Estimate one corpus/scorer/actual paired observation/quality-resource report and readonly closure milestone. Risks: declaring tiny visible fixtures general multilingual accuracy, using OCR engine scores as probabilities, changing normalization/labels after results, treating blank extraction as proof of visual emptiness, comparing unsupported native table reconstruction to a VLM grid, hiding latency/cache differences and confusing CPU RAM with GPU VRAM.

Freeze eight existing authored source/page cases: searchable PDF ASCII/known empty page; clean English PNG/scanned PDF page1/known blank scan page2; blank PNG; deliberately blurred latent-text PNG; Vietnamese table. Original files/labels remain unchanged. Run unchanged page1-based native-first `prepare_page(auto)` once and unchanged explicit `prepare_page(vlm)`→original CORE `transcribe_image` once per case. They are two explicit evaluation modes, not a runtime escalation/retry or new adapter. Original D21 model/options/deadlines/normalization/cache behavior remain. No source/body/engine label is repaired to improve a score.

Scorer uses complete NFC and whitespace-only normalization, preserving case/diacritics/punctuation and every token; no clipping, deduplication or heuristic answer repair. CER/WER are exact Levenshtein edits divided by max1 reference length and can exceed1 for insertion-heavy/blank output; they are not probabilities. For table VLM output, flatten complete table cells only for textual metrics and score exact grid/row/column/6-cell alignment separately; preserve the original full text/tables/uncertainties for this explicitly public authored evaluation. Native table text has CER/WER but no invented grid reconstruction score. Extra/missing rows/cells remain errors. The blurred case is uncertainty detection; report its latent-reference edit errors without requiring successful transcription of unreadable data.

For known authored blank images/pages, nonempty transcription is a false-positive/invention indicator. Token disagreement with other known ground truth is a bounded discrepancy flag, not certified semantic hallucination. Native raw Tesseract scores remain uncalibrated and always report English-only limitations; CORE has no confidence probability and always requires review. Two distinct frozen missing-field image questions additionally measure absence handling through accepted D61, retaining every unsupported answer and distinguishing schema/delivery from usefulness. Original D61 first2/3 remains immutable and is not rescored.

Measure sequential per-mode wall duration including its own preparation; original CORE stays resident throughout. Snapshot only the exact existing CORE process RSS in MiB and its NVIDIA compute-process allocation in MiB before/after; these are point samples, not peak/additional allocation or a native-versus-model memory comparison. CPU worker address-space512MiB/8–9CPU/25s and4MiB raster remain declared limits, not measured RSS. Native OCR makes no new GPU request, but the already loaded CORE remains in VRAM; do not attribute its allocation to native OCR or call it system RAM. Original D21 prompt cache behavior makes this a warm sequential observation, not cold-start or a model-candidate latency benchmark. D67 retains fuller context/concurrency/workload sampling.

Acceptance is complete reproducible actual observations, tested metric oracles, honest native/CORE text/grid/uncertainty/absence/latency/resource tradeoffs, preserved errors, ordinary text recovery, joined resource closure and unchanged prior556 source/model/data/runtime audit. It does not require both engines to have perfect OCR or establish an alternative model winner. Any optional dedicated OCR/Qwen3-VL candidate still needs MODEL-EVAL-006 evidence/resources/migration/rollback and the user's approval before replacement; do not download or select one here. Keep original native-first/explicit VLM routing and production restrictions.

Rollback removes/drains only new evaluation helpers and retains every original source/first score/benchmark result. No application/API/Docker/Vault/database/model/config/dependency or accepted source change.
