# ADR-030 — Deterministic source-bound private chunks

**Purpose:** Define D22 chunk identity, exact extracted-source spans, boundaries and access semantics before API changes.

**Date:** 2026-10-18
**Status:** Accepted for localhost/one worker. 30 mapping/identity/budget +29 real PostgreSQL HTTP/lifecycle cases; full700 passed in76.12s, zero skips/exclusions, real CORE/PostgreSQL. No new dependency/schema/service.

P1 depends on D17 owned namespace/ready/hash source admission, D18–D21 structured/native/OCR projections and response ownership. Estimate one or more milestones. Risks: lost table structure, unstable IDs, mixed-owner content, stale sources, oversized rows/replies and laundering OCR/model uncertainty. Reuse accepted parser APIs/workers; add no dependency/schema/cache/index/service. Transformation runs in a joined bounded host thread on already parsed data.

Add authenticated `POST /files/{id}/chunks?max_bytes=2048&source=auto&page=1&ocr_mode=auto`. Max bytes256–8192, fixed-version UTF-8 byte policy, not a token claim; tokenizer choice remains D24. Auto consumes native PDF pages, DOCX body paragraphs/heading-style sections/table rows, XLSX sheet rows/cells or plain UTF-8 TXT/MD/CSV. Images use D21 auto OCR. Explicit `source=ocr` consumes one PDF/image page with D21 auto/ocr/vlm; VLM remains explicit. Reject irrelevant page/mode combinations rather than silently ignoring options. No caller-supplied content, owner, namespace, access labels or parser responses.

Text spans use Unicode code-point offsets into the exact extracted field (not binary/XML byte offsets). Preserve original text without Unicode normalization/case folding/whitespace cleanup. Split oversized text at code-point boundaries under byte cap, without overlap/drop; do not cross page/paragraph boundaries. Blank sources are listed explicitly. DOCX heading-style/basedOn chains define section locators; table-cell paragraphs are represented once as table rows. Refuse overlapping/nested table paragraph membership or cyclic section-style chains. CSV remains lexical text, not an inferred grid.

Rows are atomic; v1 emits one row per chunk, with no cross-table/sheet/section/quality grouping. Text is canonical JSON of structured rows; source spans separately retain every original paragraph/cell field. An oversized row fails413 instead of splitting cells or truncating. Retain DOCX row/column/gridSpan/vertical merge and XLSX addresses/types/styles/formula attributes/cached values/merged ranges. Formula source/cache are data, never evaluated. OCR text and VLM table projections remain separately labeled; all source review/uncertainty/cache flags propagate. VLM always-review and English-only OCR restrictions remain unchanged.

Chunk IDs are SHA-256 of canonical JSON containing private owner/namespace/file identity, source SHA, extractor identity, chunker version/byte policy and complete chunk content/spans/structure/sections/quality. JSON serialization is sorted-key UTF-8 without text normalization. Same source/options/content repeats deterministically; changed file/hash/owner/namespace/processor/policy/content changes ID. Model output changes produce new IDs even if source bytes are unchanged.

Public source metadata includes file UUID/hash/processor/chunker/byte policy, `content_trust: untrusted`, exact locators/spans, and server-generated access labels: private visibility, authenticated principal UUID and an opaque hash of owner/namespace/file scope. Namespace itself remains internal. Labels/IDs are descriptive, not bearer capabilities; later retrieval must authorize against trusted source records, never accept client labels as authority. No cross-owner deduplication/adoption.

One chunk operation/response slot per FileService, no queue, excess429. Hold tracked task/source SH reader through joined extraction/transformation and response delivery/cancel. Reuse DOCX/XLSX/OCR contexts through response; PDF/text use the retained FD directly. Reference-count nested tracked contexts so inner completion cannot untrack an outer source owner. Incrementally bound metadata serialization before accumulating a complete reply. Independently verify the outer locked source hash and owner/ready state after chunk construction. Underlying parser gates still apply where reused; PDF chunk extraction has its own single admitted operation. No public/multiworker/load SLO claim.

Projected source text/structured-row JSON at most1 MiB,1000 combined chunks/empty records,8 MiB reply including metadata/provenance; existing parser bounds remain. Reject overflow, no partial/truncated output. Join thread work before closing FDs and retain admission through slow responses; delete may hide immediately but cannot release quota before reader close. Existing source/schema/quota/auth/backup identity unchanged. Rollback drains/removes chunk code/endpoints only.

Acceptance: exact golden page/paragraph/section/table/sheet/cell/blank mappings; Unicode byte splits and source reconstruction; preserved formula/cache/merge/OCR-review metadata; deterministic IDs under reorder/repeat and changed source/policy/access identity; owner/namespace/hash/state/resource/delete/cancel/slow-response negatives; full Vault-backed regression. D23 evaluation/repair and D25 ingestion remain future milestones.
