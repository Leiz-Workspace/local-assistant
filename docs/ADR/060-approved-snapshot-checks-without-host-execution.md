# ADR-060: Approved snapshot checks without host execution

**Purpose:** Prepare the D42 native test/lint execution policy without granting arbitrary commands, mounting a live project or treating untrusted test output as approval/quality authority.

**Date:** 2026-10-20 (Asia/Ho_Chi_Minh)

**Status:** Accepted and verified within D42 local finite snapshot scope:2461 full PASS/1536.84s,1104 related subset/192 new cases,0SKIP/exit0 and clean396-source/409-hash readonly audit. [Acceptance](../evidence/d42-checks-acceptance.json). No production execution/approval or model change.

**Reading historical bounds:** Earlier sections retain pre-implementation proposals and disposable failed probes. The final bounded contract and affinity correction below supersede earlier256KiB/process/taskset drafts:512KiB per job,16 shared-address-space threads, dedicated launcher inheritance and affinity-change denial. [Current implementation/verification](../D42_APPROVED_SNAPSHOT_CHECKS.md) records2461 full and1104 related subset PASS/0SKIP/exit0 with clean audit. Historical experiments are not additional completed acceptance gates.

**OS trust boundary:** The captured interpreter's normal isolated import paths and executable bytes are verified, but the namespace also exposes read-only trusted `/usr` for loader/system support. That tree can include system packages/tools readable by untrusted source; do not claim a hermetic image or absence of all host package contents. Host home/`.venv`/uv cache are not mounted, project hooks are not automatically loaded, and any explicit import/exec remains under the same namespaces/seccomp/resources. Package-framework compatibility is unsupported unless separately evaluated. This clarifies the implemented boundary without widening a mount, changing source or installing anything.

## Priority, dependencies, effort and risks

Roadmap D42 is P1 after accepted D41. One sandbox/check-contract milestone plus native resource/fault/cancel/HTTP/CLI and related/full regression/audit evidence. Depends on D33 owner/workspace native capabilities, D39 exact explicit run_checks approvals and D41 checkpoint/journal composition before general coding-agent release. Primary risks: shell/argument/environment injection, live host mounts, mutable approved inputs/toolchain, package/plugin/hook execution outside reviewed policy, credential/network access, process descendants/output/resource exhaustion, lost acknowledgements and false test-success claims. No new model, dependency installation, Docker/Vault/database/migration or agreed inference configuration change is proposed.

## Proposed bounded first profiles

Use finite server-defined Python stdlib unittest and Ruff static correctness profiles against a private immutable selected-file snapshot, not arbitrary pytest/package/build/shell commands. Local discovery confirmed system Python3.12 and cached Ruff0.17.1 already available; do not download/install tools/models. Ruff binary SHA256 observed `20cf97c5db04ca9c51249dec1a54cbc96c24462df280334ada04b8f3c877b746`; actual startup must require explicit trusted path/hash, copy/hash/fence it privately and mount the immutable copy read-only. The mutable tool cache itself is not mounted for execution. Do not modify cached binary permissions or the existing environment.

Stdlib unittest avoids mounting the complete project `.venv`/site-packages or processing project/global pytest plugins, `.pth` or sitecustomize on this first execution surface. Use a fixed isolated/no-site/no-bytecode interpreter command and fixed discovery targets. Ruff runs with isolated/no-cache/fixed correctness rules and one fixed worker thread. This covers the initial test/lint namespace/resource gate, not arbitrary framework/package/build compatibility. If realistic MVP cases need pytest or third-party packages, treat trusted runtime packaging as an explicit dependency before claiming those cases supported; do not install dependencies or silently mount the host environment.

Proposed source bounds:1–16 distinct explicit nonhidden relative `.py` files,8192 raw UTF-8/no-NUL bytes each,128KiB aggregate. Read through D33 kernel capabilities, stable native stat/hash/root fences and bounded joined I/O; preserve exact source bytes. Stage owner-only copies into an explicit dedicated private job root outside workspace/checkpoint roots. Once approval is published, input files/manifest/runtime are immutable; no live project mount. Selectors, commands, environment, resource budgets and tool roots are server-owned, never model/client overrides. Freeze final job/root/output count/byte/retention limits before implementation. No silent deletion of durable observations to admit new work.

## Review and launch authority

A trusted server creates a concrete run_checks review binding owner/workspace/job UUID, native source root/version, complete selected-file path/hash manifest, runtime digest, fixed profile/argv, readonly mounts, no-network/no-credential policy and exact resource/output/deadline ceilings. Display the whole manifest/command/policy within D39's32768-byte review limit; selected source remains inspectable through accepted source reads. The owner explicitly types the new request UUID in the existing CLI. No approval of a vague title, model text, old patch grant or widened command.

Before launch, revalidate original source/root/context and private input/runtime identities/hash/permissions. A changed source needs a new snapshot/review even if the old copy still exists. Consume the linked exact approved grant once immediately before starting the native supervisor. No retries, refunds, automatic command after proposal/review or old-grant recovery after restart. Program output cannot request a different command or approve any write. Keep all five earlier readonly model tools unchanged; later D43 trusted composition may request only this finite reviewed execution surface.

## Native isolation and observations

Reuse existing bubblewrap/prlimit supervision with fresh process/network/user namespaces, no capabilities, actual unprivileged UID/GID, cleared allowlisted environment, readonly trusted system runtime and only readonly captured inputs/tool binary. No host workspace/home/Vault/socket/cache mounts or leaked inherited descriptors. Native preparation probes exposed the D41 FD gap; ADR-061 consumes setup descriptors and protects document stdin. D42 must use consuming mount-FD options and prove original setup FD numbers cannot traverse host parents, rather than binding /proc/self/fd strings and relying on absolute-path absence. After all input/runtime mounts, remount the ephemeral root scaffold readonly; only the explicit bounded scratch child mount may remain writable. Request metadata mounts must precede this final remount (ADR-061 DOCX/XLSX ordering lesson). Native tests must deny arbitrary root scaffold creation as well as host/FD writes. A private bounded tmpfs may be writable for test temporaries; local bwrap supports `--size BYTES` for the next tmpfs. Proposed16MiB scratch,512MiB address space,2s soft/3s hard CPU,16 process ceiling,64 FDs, no core dumps, fixed per-file-size/output/wall ceilings; finalize native probes before accepting these limits. Ruff thread count is fixed to1. Isolation/toolchain failure has no host/unsandboxed fallback.

Parent pumps bounded nonblocking stdin/stdout/stderr, kills/joins the owned process group/namespace on timeout/cancel/output violation and retains source/runtime capabilities until all work joins. Record server-started/exit/signal/timing/resource-policy observations and privately bounded untrusted output; audit only IDs/status/count/hash, no raw source/program output/nonce/credentials. Treat non-UTF8 output explicitly rather than pretending a lossy decode is exact. Cancellation after execution cannot undo effects in the already isolated scratch environment or erase the receipt; it never modifies the host project. Drain checks before their approval/workspace dependencies close.

Command exit0 and printed PASSED/JSON/JUnit are untrusted check observations, not proof of meaningful assertions or passing functional oracles. Untrusted test/conftest/source can exit early or forge output. Do not parse a magic success marker into permission, quality PASS, automatic patch acceptance or roadmap completion. Host-authored frozen fixture oracles and externally observed canary/network/resource/cancellation effects establish this milestone's policy gate. Later D43/D46 must independently define workflow/quality thresholds and retain actual model failures.

## Draft finite storage and receipt contract

Proposed local process scope:32 retained jobs globally/8 per owner,256KiB reserved per job,8MiB job reservation ceiling plus one independently bounded64MiB complete private Python/stdlib/Ruff runtime capture (observed pinned Ruff size23938560 bytes). Use a distinct explicitly configured existing owned0700 root, native ancestry-disjoint from workspace and checkpoint roots; no host root registration, implicit directory creation or automatic retirement. Incomplete/unknown entries remain charged and fail closed. Restart invalidates ephemeral run grants; retained intent/output is historical evidence, never permission to resume. Stage/source/runtime write or fsync failure before launch prevents execution; record durable intent before grant consumption, and retain truthful started/exit/uncertainty state if later recording fails. Do not infer a completed check from a ready/started journal.

Pending source selection remains1–16 unique nonhidden `.py` paths, each<=256 UTF-8 path bytes/8192 raw bytes,128KiB aggregate. Bind source identities/root/context and exact hashes, selected immutable bytes and trusted runtime/profile digest into the complete review. Reject review overflow, changed native inputs, runtime mismatch, wrong owner/workspace/profile/grant, expired nonce or replay before child launch. Source inspection budget is cooperative and separate from the120s approval lifetime. No runtime fixture/plugin/package import occurs in the host process.

Proposed native execution policy:10s parent wall deadline,2s soft/3s hard CPU,512MiB virtual address-space ceiling,16MiB private tmpfs scratch,1MiB per-file scratch limit,16 processes,64 FDs,core0, fixed one-CPU affinity. Enforce stdout16384/stderr4096 raw-byte ceilings in the parent, kill and join before returning overflow/cancel/timeout. These are draft bounds before implementation, not tested production guarantees. Exact startup/drain and private-file/journal/native fault/cancel/HTTP/CLI tests remain required after D41 acceptance. No approval/real job is created by this document.

## Draft runtime capture refinement

The immutable runtime promise includes Python executable and stdlib, not only the Ruff binary. Native disposable capture copied the existing Python3.12 executable plus624 stdlib files into `/runtime/bin/python3.12` and `/runtime/lib/python3.12` (22143399 bytes before Ruff). Actual isolated startup resolved sys.prefix and encodings/unittest exclusively beneath `/runtime`; no installation or host `.venv` mount. Retain `data/backups/d42-draft-private-python-probe.json`. Exclude bytecode caches, external packages and sitecustomize/usercustomize. Flatten only the explicitly verified internal sysconfig alias to ordinary captured bytes; reject external/unknown aliases rather than copying `/etc` configuration.

This refines the earlier Ruff-only storage draft:64MiB total runtime cap, at most800 files/4MiB per stdlib file and32MiB per executable, plus existing8MiB job reservations. Capture/fence bounded owner-controlled private copies and a complete file path/size/SHA256 manifest before enabling the service; source/tool changes or runtime corruption invalidate launch without grant recovery. Copy the already installed trusted versions only. No third-party runtime support, download, dependency upgrade or model change. `/usr` remains readonly trusted operating-system loader/shared-library support; privileged OS/kernel changes are outside the private capsule guarantee and require service drain/revalidation. Do not claim a complete immutable OS image.

This is P1 within D42's existing approved-input/runtime isolation acceptance gate, depends on D41 and the measured local Python/Ruff inventory, and adds one bounded capture/integrity component plus native/fault tests. Main risks are omitted runtime files, alias/config leakage, quota undercount and mutable approved tools; failure disables checks without changing source or reverting models. No separate feature/day is automatically scheduled. Finalize after the actual D41 gate passes.

## Final D42 v1 implementation contract (supersedes draft bounds)

| Dimension | Final first-surface policy |
|---|---|
| Profiles | `python_unittest` fixed isolated stdlib discovery; `ruff_check` fixed isolated/no-cache/no-noqa static E9/F on snapshot, no fixes/config/plugins |
| Source |1–16 unique explicit nonhidden `.py` paths,<=256 UTF-8 path bytes/4 components,8192 raw UTF-8/no-NUL bytes each,128KiB aggregate; expected SHA256 supplied for every file |
| Approval | Exact owner/workspace/job/source identities/hashes, runtime inventory digest, fixed argv and complete policy;120s lifetime, one linked fresh run_checks grant |
| Storage | Separate explicit owned0700 root, native ancestry disjoint from workspace/checkpoint roots;32 retained jobs/8 owner,512KiB reservation each/16MiB total jobs,64MiB shared captured runtime; no retirement/deletion/replay |
| Inventory |<=128 job entries,800 runtime files/128 directories; manifest<=128KiB, job/review/receipt<=32768 bytes; independently bound actual allocated storage |
| Runtime | Existing Python executable+stdlib/private Ruff copies and exact SHA256 manifest; no external package/startup hook or model installation; readonly trusted OS loader/shared-library support |
| Native process | Strict fresh user/network/process namespaces, nested userns disabled/asserted, no capabilities, cleared env, consumed readonly snapshot/runtime FDs, readonly root,16MiB writable scratch |
| Execution |10s parent wall,512MiB shared process address space,2s soft/3s hard group CPU,1MiB file size,64 FDs,16 threads,core0; fixed one currently allowed CPU and allocator/thread settings |
| Thread-only | Sealed20-instruction x86_64 seccomp filter rejects affinity changes, fork/vfork and non-thread clone; clone requires VM/SIGHAND/THREAD, clone3 returns ENOSYS for libc fallback; unknown architecture killed and x32 denied |
| Output | stdout16384/stderr4096 raw bytes, explicit bounded base64+hash/size, no marker/exit0-to-quality/approval inference; no raw output in logs |
| Lifecycle | Nonqueued single operation, durable prelaunch intent then one-shot consumption, joined cancel/timeout/output/child failure/drain, honest postlaunch persistence uncertainty, no retry/refund/automatic run |

Thread-only policy is P1 inside the existing D42 resource gate: prevents subprocesses multiplying per-process address-space/CPU budgets while retaining bounded runtime threads. Native disposable sealed-filter probe completed four Python threads and denied fork EPERM1 (`data/backups/d42-thread-only-seccomp-probe.json`); actual Ruff compatibility/resource/fault/descendant tests remain required. No new dependency is needed. Programs requiring subprocesses/multiprocessing are unsupported by v1 and need an assessed later runtime/resource policy; do not silently weaken the filter. This bounds user address space, not a measured RSS/VRAM or whole-system kernel-memory guarantee.

512KiB job reservation refines the earlier256KiB draft to include bounded directory blocks, source bytes, manifest and terminal output under the selected path-depth limit.64MiB runtime plus16MiB job reservations gives80MiB admission ceiling; unknown/incomplete entries fail closed and remain reserved. No durable observation is deleted to admit a job. All native policy and resource failures must remain observations and never grant source edits or production execution permission.

## Native affinity bypass correction before acceptance

Actual new controlled source changed the taskset initial CPU0 affinity back to all allowed CPUs0–15. One native assertion FAIL/.13s, retained at `data/backups/d42-pre-affinity-fix.log`; complete pre-fix source and hashes in `data/backups/d42-pre-affinity-fix-full-files.zip`. Earlier65/87 native checkpoints did not test this path and are not complete D42 acceptance. CPU hard limit/network/source boundaries remained in force; no host credential/project write occurred.

Set affinity in one newly owned host launcher thread before Popen; only that Linux thread is pinned, and the child inherits the reviewed mask. The controller/file-I/O thread keeps its original affinity. Add sched_setaffinity syscall203 denial to the sealed x86_64 BPF (20 instructions); remove taskset from the child command because it must not bypass the same filter. Join the launcher and all native work before releasing pins or reporting cancellation/startup errors. Thread creation/acknowledgement failure must still signal stop and join any actually started launcher. No reusable host thread is left pinned after an execution attempt; no unsandboxed or affinity-widening fallback. Native source reset must now fail EPERM, actual Ruff/threads must remain compatible, and parent affinity/launcher/namespace inventories must remain unchanged after success/failure/cancel/timeout.

Existing uv cache Ruff uses two hardlinks. Permit that operator-configured seed only for stable SHA256 preflight/copy; require the exact declared digest and create a fresh single-link private executable. Reject source/project/private storage aliases by default; no direct cache mount, host permission change or generalized hardlink exception. Initial capsule integration2 PASS/2 FAIL/.24s identified this compatibility requirement; corrected full private Python/stdlib/Ruff paths plus native contracts reached87 PASS/5.65s before the new affinity-negative case.
