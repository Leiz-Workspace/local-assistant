# ADR 096 Offline nominated TTS comparison

**Purpose:** Define D70's original Qwen3-TTS-0.6B versus Piper comparison, language/voice/license boundaries, fixed synthesis and inspection protocol before candidate provisioning or generation.

**Date:** 2026-10-22. **Status:** Accepted for offline evaluation after D69 closure`5653de4`/readonly612-source audit. No TTS/ASR/VAD/default selection or deployment approved.

## Scope, priority and dependencies

MODEL-EVAL-005/D70 is existing P2 work,1–2 evaluation milestones, dependent on verified VI/EN capability and voice licensing, bounded offline generation, frozen common authored texts, explicit source/codec identities, genuine audio inspection and original CORE/data/runtime audit. Risks include pretending documented10-language Qwen support includes Vietnamese, confusing Auto diagnostics with supported language capability, comparing different voices/precision/decoders as architecture-only quality, claiming ASR roundtrip is naturalness/MOS, unreported truncation/sampling retries, hidden auxiliary model assets and promoting an evaluated voice/runtime to a default without owner approval.

Preserve every612 prior source file, all D68/D69 first results and model/SDK/corpus, every original CORE/UNRESTRICTED/embedding/reranker/VLM role/configuration, D24 E5 rollback, data/collections/services/Vault/Docker/database. Provision only nominated TTS-family evaluation artifacts and necessary codec/phonemizer dependencies into an owned ignored directory. No microphone, reference-speaker recording, voice cloning, new API/server/profile/default or model replacement.

## Frozen cases, synthesis and output integrity

Before predictions freeze six authored English/six Vietnamese neutral short text cases (greeting, question, numbers spoken as words, date spoken as words, instruction and longer phrase), at most160UTF8 bytes each. References are authored test texts, not independently human-rated TTS truth. Qwen attempts6English+6explicit-Vietnamese capability checks+6separate VI-Auto diagnostics; Piper generates6per language in separate fresh voice processes.24potential first waveforms; expected explicit unsupported-language observations are not correct empty audio or full successful VI coverage. No output-dependent retry/seed/text/voice/hint/threshold change.

Qwen uses official recommended sampling: seed7 per case, do_sample=True/top_k50/top_p1/temperature0.9/repetition_penalty1.05, subtalker samplingTrue/top_k50/top_p1/temperature0.9, max_new_tokens192, non_streaming_mode=True, no instruction/reference prompt. A transparent generate observer may record original returned codec lengths without replacing outputs or changing arguments; retain exhausted/failed generations as failures, not complete speech. No duplicate return_dict flags. Piper uses speaker0, voice config's default noise scales, length_scale1, normalize_audioTrue/volume1, no alignments. Materialize every lazy audio chunk, preserve standard returned float32 audio/voice-specific processing and record first-yield/complete time; these different APIs are not a controlled architecture-only comparison. Qwen synchronous returned audio availability equals completion of its call; do not invent first packet/streaming TTFA.

Validate original complete mono float32 waveforms/sample rates/counts/finite range, store private WAV/raw hashes and duration/peak/RMS/clipping/leading-tail silence diagnostics. Keep all first failures and raw bytes; no trimming, gain repair, silence removal, host pronunciation/number correction or resynthesis. Standard engine normalization is recorded. First calls may include lazy initialization; files/cache may be warm, no cold-storage/SLO claim.

Naturalness review requires actual emitted audio inspection with a retained per-output qualitative review; same-agent listening is labelled as such, not independent human MOS or general voice-quality certification. Optional equal-level compressed listening copies are separate hashed inspection artifacts; original audio remains authoritative. ASR roundtrip/acoustic metrics alone never substitute for naturalness. If audio inspection is unavailable, leave that criterion open rather than manufacture listening observations.

As a separate intelligibility diagnostic, resample all successful native outputs to common16k float32 using the same frozen scipy resample_poly method, retaining original/sample hashes/counts. Then run existing frozen Qwen3-ASR-0.6B once per waveform after all TTS processes retire, with fixed language hints and unchanged D68 scorer. This proxy may favor a related model family; it is not independent text correctness or naturalness/MOS. Retain every mismatch and all OOD/unsupported distinctions; no model selection from proxy scores.

## Isolation, measurements and acceptance

For the separate ASR input only, common rational resample_poly output may overshoot unit amplitude through filter ringing; if its peak exceeds1, scale the whole resampled buffer by reciprocal peak and record that exact factor/hash/count. Never clip/trim or overwrite the native TTS waveform. This declared input-bound normalization is not a repaired TTS score or naturalness enhancement. Listening copies may additionally normalize RMS with headroom and use a recorded codec; only those separate inspection copies change gain/encoding.

Only an empty owned per-run output directory is mounted writable for exclusive0600 float32/WAV results; model/source/SDK/text corpus remain readonly. Input/output case filenames are fixed bounded identifiers, special files/links/overwrites are refused, per-file16MiB and cumulative64MiB output limits apply, and parent revalidates complete hashes/counts. Native waveform duration cap20seconds; exhausted/overlong output is retained as a failed observation, never silently shortened to fit ASR. This output capability does not expose any original source/model/data/credential path.

One candidate/voice process at a time; no overlap with ASR/full suites. Offline credential-free PID/filesystem/network/GPU namespace, selected model/source/SDK/corpus readonly, synthetic UID entry,128MiB private tmpfs; CPU affinity0,1. Initial TTS execution caps12GiB address space/3600CPU seconds/1800wall seconds accommodate the checkpoint+mandatory codec loaded as CPUfloat32, not a predicted minimum RAM requirement. Plan about2.62GB candidate weights plus isolated SDK/outputs, up to7.5GB new apparent evaluation storage before measurements. Qualify import/load and separate non-corpus text before common cases. Retain any failures before adjusting feasibility. Original CORE remains loaded; record PID/start/command/RAM/NVIDIA allocation/text recovery before/after. Measure import/load, genuine first-return/total synthesis, audio duration/RTF, lifetime process peak RSS/CPU and cleanup. ASR replay retains its existing8GiB/1200CPU/900wall worker caps and mounts only D70 replay inputs, without modifying D68 directories/code.
