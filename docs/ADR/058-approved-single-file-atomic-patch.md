# ADR-058: Exact approved single-file source replacement

**Purpose:** Define D40 concrete full-file proposals/unified diffs and native atomic replacement after exact D39 approval.

**Date:** 2026-10-20 (Asia/Ho_Chi_Minh)

**Status:** Accepted/implemented after D39 `8b9c369`:2172 full PASS/1543.21s,0 SKIP,exit0;621 related PASS/8.32s and clean355-file/data/config audit. [Acceptance](../evidence/d40-patch-acceptance.json). Local single-file fixtures only, no production edit release or durable rollback claim.

## Priority, dependencies and risks

P1 after D33 native scope and D39 explicit approvals; one bounded single-file edit milestone plus fault/transport/regression/audit evidence. Risks: stale source/root, path/link/mount escape, metadata loss, review/commit mismatch, cancellation around commit, lost acknowledgements and mistaken claims of atomic multi-file or hostile-process compare-and-swap. Preserve D33 readonly guards, selected models, database, migrations, Vault and infrastructure. No host workspace is registered or production action approved by this work.

## Decision and scope

Add a separately default-off patch service requiring workspace and approval services. First scope: replace one existing nonhidden regular single-link UTF-8 file with complete proposed text; at most8192 raw bytes before/after, no NUL, no create/delete/path rename/multi-file edit. Accept only relative path, exact expected base SHA256 and replacement text. Source/root authorization uses unchanged D33 kernel capabilities; no client owner/root/command/mode/diff/approval override. Reject unsupported platform, binary/oversized source, non-owner/set-ID/group-or-world-writable source/parent, inaccessible group preservation and nonempty ACL/xattr metadata rather than silently dropping it. Preserve eligible mode/UID/GID. The source remains data; no model, Git, hook, import or command executes.

Proposal creation performs reads only. Server captures exact raw source hash/stat fingerprint, root and parent identity and retained root pin, derives a source-version digest, generates a complete replacement/unified diff (including explicit missing-final-newline markers), and creates the concrete D39 patch-review artifact. Bind proposal UUID, path, source version/base hash, replacement/hash, permissions and diff. The full immutable review must fit D39's32768-byte limit; reject excess rather than truncate. No-change proposals fail. At most16 proposal records/root pins,120-second process-local lifetime; terminal records may retire at capacity. Expired records cannot apply; bounded idle pins are closed on access/capacity/shutdown. Restart invalidates both proposal and approval; no recovery/replay grant. Orphan temporary-file crash recovery is not claimed before durable D41 journal/checkpoint work; never guess ownership or resume an old edit.

Only the explicit owner can fetch/apply a proposal. Before preparing a temporary file, require an already-approved unexpired exact D39 scope/artifact. A model request or merely pending review cannot cause even temporary workspace writes. Revalidate actual source/root/parent identity, exact bytes/hash and eligible metadata; changed source requires a new proposal/review. Serialize writers with nonqueued service admission and advisory file locking for cooperating clients. Readonly services remain independent and their final fences detect source replacement.

Prepare a uniquely named owner-only hidden O_EXCL/no-symlink temporary file inside the admitted parent FD, write all exact bytes, preserve eligible metadata and fsync it. Revalidate again, consume the exact one-shot approval immediately before mutation, then use same-directory FD-relative atomic rename over the existing file and fsync the parent. Cleanup may unlink only this acknowledged-owned temporary entry. Resource deadline5 seconds is cooperative; cancellation signals and joins file work/descriptor ownership and cannot preempt uninterruptible kernel I/O.

Successful rename is the commit point. Record applied state before returning; a later directory-fsync failure is applied_durability_uncertain, never reported as nothing-applied. If a rename acknowledgement fails, inspect the expected prepared inode; an indeterminate outcome is explicitly outcome_unknown and cannot be retried automatically. Cancellation/lost HTTP acknowledgement after commit does not silently roll back or erase the applied receipt; owner status queries remain authoritative. Before-commit failure/cancellation leaves original bytes intact and cleans the owned temporary entry. If approval was consumed before failure, it cannot be reused or automatically retried. Keep bounded original bytes for local inspection; durable Git checkpoint/rollback is D41 and must precede general release. This milestone's mutation tests operate only on disposable fixtures, not a real configured project.

Atomic rename makes one complete file visible at the commit point; it is not a multi-file transaction or atomic compare-and-swap against arbitrary uncooperative external filesystem writers. Root/parent/source final authorization is a pre-commit fence under the existing admission-time/host-process limitations. Do not claim post-fence path membership or prevention of all hostile same-UID/process races. Production readiness requires subsequent checkpoint/rollback/execution/injection/MVP gates.

## Lifecycle, acceptance and rollback

Drain active patch work and close all proposal pins before invalidating approval state or closing workspace dependencies. Audit server proposal/request IDs, stable status/hash/count only, no source/replacement/diff/nonce/credentials. Test actual approved full-file/native Unicode/CRLF/no-final-newline/mode/hash results, no writes before explicit consent, foreign/unknown/path/link/mount/metadata denial, source/root/parent version changes, replay/expiry, file/dir-fsync/rename/temporary cleanup faults, both cancellation orderings around commit, concurrency and all FD ownership paths. Include actual local HTTP/CLI approval→apply on a synthetic fixture and unchanged-source denial cases, then related D33–D39/lifecycle/auth/readonly-source regressions and data/config audit. Preserve the immutable first D38 four-success/two-failure result without score replacement or selection. Necessary D38 live-test artifact-only change writes subsequent full-regression measurements to private data/backups/d38-latest-core-observations.json; frozen cases/model/first public report remain unchanged, and later outcomes are separately retained rather than substituted for the first score. Disable/drain the new service to roll back feature availability; D41 separately supplies durable source rollback. D40 PASS is limited to the evidenced local single-file contract; durable checkpoint/rollback remains D41 before general release.
