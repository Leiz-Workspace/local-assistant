# D59 durable bounded research sessions

**Purpose:** Explain persisted progress, explicit boundary resume, retained archives and truthful interruption handling without reviving source/report authority.

**Date:** 2026-10-21. [ADR-078](ADR/078-durable-bounded-research-sessions.md). These new components are unwired; original522 accepted D58 source/config files and production feature flags are unchanged.

`PrivateResearchSessions(root, catalog)` opens an explicitly provisioned private0700 directory outside registered workspaces. The trusted server supplies the catalog; no cwd/default path, production directory provisioning or database/Vault/service change occurs. Accepted `PrivateCheckpointRoot` guards remain unchanged: native root/file identity, no symlink or mount traversal, owned single-link0600 files, exclusive nonblocking process flock and nonqueued thread admission. The owning OS UID/operator and local filesystem are trusted. Hashes detect corruption; they do not protect against compromise of that UID.

`ResearchSessionService(store=..., planner=..., reports=..., exports=...)` owns one nonqueued operation. `create(owner, goal, claims)` records exact normalized inputs without tool work. `advance(owner, run_id)` reserves discovery before async dispatch, performs one accepted D54 plan and at most three sequential provider queries, archives the complete original result and pauses. It never automatically chooses URLs from those results or runs another stage. An explicit `advance(owner, run_id, fresh_selections)` verifies fresh D51 source spans before reserving publish, invokes one accepted D57 report assessment, durably checkpoints the complete report, then invokes one accepted D58 DOCX/PDF export and commits complete output.

The fixed graph is ready → running/discover → paused → running/publish → complete. A session reserves each of the two stages once, without refunds or reset: at most two model completions, three provider attempts and one native batch through the accepted dependencies. Existing per-component quotas apply additionally; they are process-local limits, not durable cross-process billing or a site-wide quota system. No background polling/tool loop, arbitrary command/path/format/budget, provider fallback or automatic retry is introduced.

Every attempt reservation is written/fsynced before dispatch. Each immutable archive is completely written/fsynced, its directory fsynced, then its exact hash/length acknowledged through atomic fsynced journal replacement. Journals are strict32KiB JSON; complete discover/report/export blobs are bounded128KiB/256KiB/9MiB. Max16 retained sessions/four per owner, bounded entries per directory, no automatic eviction. Capacity exhaustion refuses new work and preserves existing bytes. Local filesystem operations have bounded data volume; fsync supplies host filesystem durability semantics, not a hard I/O-latency or power-loss guarantee.

Cancellation, deadline and finite failure join the entire owned task before releasing admission and record terminal interruption. Repeated cancellation waits for cleanup. The service's authenticated `cancel(owner, run_id)` joins only that owner's active caller; foreign/missing IDs share one finite error. `shutdown()` joins only session-owned callers, leaving store closure and shared planner/report/export/evidence/model/provider lifetimes externally owned. Uncertain cleanup or storage publication poisons admission.

Explicit `recover()` marks previously running journals interrupted and performs zero tool calls. A killed/in-flight call might already have reached the model/provider/native runtime; replay would risk duplicate work. Its original attempt remains spent, its prior acknowledged bytes remain readable, and that session cannot retry. Bounded unacknowledged candidate/temp files remain preserved without being promoted to committed artifacts. Unknown/malformed/unsafe storage fails closed for operator review; it is never silently deleted or repaired.

Recovery at a completed discovery boundary can proceed in a new process only with newly authenticated source spans. Old source/report receipts, proof keys and monotonic deadlines are not persisted or revived. The archived report contains complete original claims/assessment/quotes/provenance/Markdown and explicit unknowns, but cannot authorize a new export. If publication was interrupted after report generation, that draft remains readable as an archive; a separate future evaluated policy is needed for any rebuild/retry. A fully committed DOCX/PDF archive can be read after restart without live source proofs: this is retrieval of existing owner-bound untrusted bytes, not source revalidation, current freshness or new export authority.

`status` and `archive` require exact authenticated UUIDs. Logs retain only finite states/error codes/counts, never owner IDs, goals, claims, quotes, proof keys, paths or native stderr. Stored artifacts are private plaintext under the configured OS boundary; no encrypted/distributed artifact service is claimed. Stored JSON is never executed or parsed into a live receipt/tool instruction.
